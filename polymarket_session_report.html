一、会话内容梳理

1. 你的原始问题

你提供了两个仓库： 2026-worldcup-prediction-market 和 polymarket-sports-mm， 希望我结合相关项目，说明如何利用 Polymarket API 获取世界杯实时市场交易数据并做交易。 你特别关心三件事：API 能拿到哪些信息、如何判断策略、API 能直接执行哪些操作。

2. 我给出的核心判断

  • Polymarket 的工作流可以拆成四层：市场发现、行情读取、策略判断、认证下单与对账。
  • 最稳妥的数据来源是官方的 Gamma API、Data API、CLOB API 和 WebSocket。
  • 世界杯场景里，实时盘口、midpoint、spread、last trade、比赛状态和订单回执是最关键的数据面。
  • 策略上通常分成方向性交易和做市/奖励型交易两类。
  • 实盘要把撮合、撤单、heartbeat、仓位限制和风控放在同一条闭环里。

3. 两个项目分别代表什么

模型层 2026-worldcup-prediction-market 更偏世界杯概率模型、历史回测和赔率分析。 它适合当成“信号生成器”：先算出你认为的 fair value，再与市场价格比较。

执行层 polymarket-sports-mm 更像一个可直接参考的做市/报价器。 它的核心是：用 midpoint 附近的双边限价单获取流动性奖励，靠 size skew 表达观点，而不是大幅偏移价格。

4. 我建议的使用方式

  1. 先用 Gamma API 找到世界杯相关市场和 token。
  2. 再用 CLOB API 或 WebSocket 拉 orderbook、midpoint、spread、last trade、历史价。
  3. 把你的世界杯模型输出当 fair value。
  4. 用 `edge = fair value - market price` 判断是否值得交易，并把手续费、滑点和 tick size 一起计入。
  5. 如果是做市策略，优先用 midpoint 附近的双边挂单，再按仓位做 size skew。
  6. 上线后要用 User Channel / 订单查询接口做回执和对账。
你后面要做的半自动工具，最佳切入点不是“先预测”，而是“先把持仓、盘口、回本价、翻倍价和自动挂单闭环做好”。 这样后期无论接预测模型还是接分析模块，都不会推倒重来。

二、世界杯市场实时数据字段清单 + 对应 API 路径

这部分按你做工具最需要的数据来整理，不追求“官方接口全集”，只保留和实盘最相关的字段。

数据层 关键字段 用途 对应 API / 通道
市场发现 market slug、condition_id、token_id、title、active、closed、archived、sport、market_type 找到世界杯相关市场，筛选 winner / group / head-to-head / prop Gamma API：`GET /events`、`GET /markets`、`GET /market/{slug}`、`GET /sports`
赛事状态 live、ended、period、score、participants、start_time 决定赛前、赛中、赛后不同策略 Gamma API 事件接口 + Sports WebSocket
盘口 bestBid、bestAsk、midpoint、spread、tickSize 定价、挂单、计算可成交区间、识别套利/偏差 CLOB API：`GET /orderbook`、`GET /market-price`、`GET /midpoint`、`GET /spread`、`GET /tick-size`
成交流 lastTradePrice、lastTradeSide、trade time、trade size 判断市场是否开始移动，追踪真实成交方向 CLOB API：`GET /last-trade-price`、`GET /trades`；Market WebSocket
历史价格 price history、candles、time series 回测、趋势判断、异常波动识别 CLOB API：`GET /prices-history`、`GET /batch-prices-history`
流动性 liquidity、volume、open interest、top holders 判断能否进出场，避免薄市场被滑点吃掉 Gamma / Data API：`GET /markets`、`GET /open-interest`、`GET /top-holders`
费用 fee rate、rebate、maker reward 计算净收益，判断 quote 是否有正期望 CLOB API：`GET /fee-rate`；Rebates：`GET /current-rebated-fees`
仓位 positions、avg entry cost、qty、market value、unrealized PnL 核心的风控与展示层，决定你“现在赚了多少/亏了多少” Data API：`GET /current-positions`、`GET /closed-positions`、`GET /total-value-of-a-users-positions`
交易订单 order id、side、price、qty、filled size、status、remaining size 自动挂单、改单、撤单、部分成交处理 CLOB API：`POST /orders`、`DEL /orders/{id}`、`GET /orders/{id}`、`GET /user-orders`、批量下单/撤单接口
交易回执 fills、fills time、trade attribution、user activity 成交确认、资金对账、策略复盘 Data API：`GET /trades`、`GET /user-activity`；User WebSocket
认证与会话 API key、secret、passphrase、L1 signer、heartbeat 下单认证、维持会话、防止自动撤单 Authentication、`POST /heartbeat`

你这个工具最重要的 6 个实时指标

  • 当前盘口价：best bid / best ask / midpoint
  • 当前成本：持仓均价、总投入、手续费
  • 回本价：按持仓和手续费反推的盈亏平衡价格
  • 翻倍价：按当前成本和数量反推目标价位
  • 流动性质量：spread、深度、成交活跃度
  • 订单状态：挂单、部分成交、撤单、成交回执
如果你现在先做“半自动工具”，最实用的起点是： 先读市场和订单，再算成本/回本/翻倍，再加一个按钮或开关去做自动挂单。预测模块可以后接，不会影响前面的数据与交易闭环。

三、半自动工具的功能拆分

按你的描述，这个工具不需要一开始就做得很重。先把可视化和交易闭环做稳，预测和分析后续再加。

第一阶段：持仓与盘口监控

  • 市场列表页：只看你买过或关注过的世界杯市场。
  • 单市场详情页：展示盘口、midpoint、spread、last trade、最近成交。
  • 持仓卡片：数量、均价、当前价值、浮盈浮亏、回本价、翻倍价。
  • LOB 变化：best bid/ask 的刷新、深度变化、盘口跳动提醒。

第二阶段：半自动执行

  • 按条件自动挂单：比如 midpoint 附近挂 bid/ask。
  • 自动撤单重挂：盘口移动后重新定价。
  • 仓位上限：单市场最大仓位、总敞口上限。
  • 损失限制：日内亏损上限触发后停止自动操作。

建议的计算方式

回本价 = (总买入成本 + 交易手续费) / 持有数量

如果是 YES 票：
  盈亏 = (卖出价 - 成本价) × 数量 - 手续费

翻倍价可按目标收益反推：
  目标收益 = 当前总成本
  目标卖出价 = (总成本 + 手续费 + 目标收益) / 数量

实际实现时要把 fee、tick size、滑点、部分成交和撤单成本一起算进去。单看标价会高估可执行收益。

后期可扩展内容

  • 预测模块：接你的世界杯模型，算 fair value 和 edge。
  • 分析模块：统计每个市场的胜率、持有时间、成交质量。
  • 策略模块：方向性交易、做市、区间挂单、事件驱动交易。
  • 风控模块：最大敞口、最大回撤、黑名单市场、自动停机。
